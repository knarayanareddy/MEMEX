# MEMEX review

## Scope and verdict

Revision `efe68e07df8d38988eb773f1485da64a0f375ba6` is an implementation-stage local daemon, not a verified privacy certification. **Overall confidence: medium, sampled static only.** The reviewed evidence covers the snapshot manifest, CI/workflow metadata, Docker/Compose, `SECURITY.md`, CLI/TUI/web slices, `memex/api/app.py`, `memex/api/middleware.py`, and two targeted SHA-pinned read-only source rereads for `memex/api/routes/memory.py` and `memex/protect/forget.py`. Ingestion internals, most database code, most tests, and backup/restore mechanics were not inspected. Runtime, tests, browsers, network observation, and deployment were **not run**.

## Architecture and boundary

The [manifest:47-48](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/pyproject.toml#L47-L48) exposes `memex`; the [API factory:21-33](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/app.py#L21-L33) wires SQLite, Chroma, Kuzu, retrieval, chat, queueing and the forget manager into one FastAPI app. The web client hard-codes [`const API = 'http://127.0.0.1:7700';`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/web/static/app.js#L6-L7), and Compose publishes only [`"127.0.0.1:7700:7700"`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/docker-compose.yml#L19-L20). In the sampled route layer, forget and verification are exposed as [`@router.delete("/{document_id}")`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/routes/memory.py#L88-L98), [`@router.delete("/source/{source_type}")`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/routes/memory.py#L101-L106), and [`@router.get("/forget/verify/{document_id}")`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/routes/memory.py#L109-L115). This sampled review does not prove browser-origin isolation, same-host multi-user separation, or backup/privacy behavior.

## Findings ledger

- **MX-01 — Medium, confirmed static, high confidence:** [Dockerfile:33-34](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/Dockerfile#L33-L34) uses the exact pattern [`RUN curl -fsSL https://ollama.com/install.sh | sh`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/Dockerfile#L33-L34). That is a mutable build-time supply-chain dependency with no reviewed artifact digest or provenance check in the sampled build path. It does not by itself prove runtime exfiltration.
- **MX-02 — Medium, historical CI, high confidence:** The pinned snapshot records recent run [`27377779621`](https://github.com/knarayanareddy/MEMEX/actions/runs/27377779621) as a failure on this SHA, while the README still shows [`tests-150%20passing`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/README.md#L2-L6). The failed job logs and root cause were not inspected, so this is historical evidence of an unresolved pipeline failure, not a current root-cause diagnosis.
- **MX-03 — High, confirmed static, medium confidence on impact:** The sampled request gate is peer-address based: [`allowed = ("127.0.0.1", "::1", "localhost", "testclient")`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/middleware.py#L33-L35). In the sampled route code, destructive and verification endpoints simply fetch app state and execute, e.g. [`forget_mgr = _get_forget_manager(request)`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/routes/memory.py#L91-L92) and [`result = await _run_sync(forget_mgr.verify_forget, document_id)`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/api/routes/memory.py#L113-L114). No caller identity, user/session ownership, or per-document authorization check is visible in this sampled route/middleware slice. That confirms the reviewed boundary is weaker than user-scoped authorization; hostile-browser, DNS-rebinding, and same-host multi-user exploitability remain untested.
- **MX-04 — High, confirmed static, medium confidence on completeness:** The inspected forget path attempts direct deletion rather than a normal soft-delete flag: [`self._chroma.delete_vectors_by_ids(chunk_ids)`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/protect/forget.py#L75-L81), [`self._kuzu.delete_mentions_for_document(document_id)`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/protect/forget.py#L83-L86), and [`self._sqlite.delete_document(document_id, conn=conn)`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/protect/forget.py#L88-L108), then persists a forget record with [`self._sqlite.insert_forget_log(...)`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/protect/forget.py#L110-L119). On failure it can mark [`DocumentStatus.FORGET_FAILED`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/protect/forget.py#L128-L145). The sampled verification path returns [`{"verified": all_clear, "stores_checked": checks}`](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/protect/forget.py#L195-L224) after checking vectors, chunks and mentions only. So the sampled source supports a physical delete attempt across live stores, but not a verified claim about backup copies, restored instances, cache/log remnants, or whether the SQLite document row and forget-log contents are independently read back after deletion.

## Five-discipline assessment

**Correctness:** The sampled forget path is a multi-store sequence with a partial-failure branch, not just documentation. That makes independent readback important: success booleans are set as the code progresses, and `verify_forget` checks only sampled live-store conditions. Initialization, retries, and concurrent ingest/forget behavior were not traced.

**Automation/testing:** The pinned CI failed (MX-02). The tree lists invariant, integration and unit tests, including `tests/invariants/test_forget.py`, but their assertions were not inspected. A README badge is not proof that forget, redaction or local-only claims currently hold.

**Operations:** [Compose:19-24](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/docker-compose.yml#L19-L24) binds the API to loopback and mounts watched directories read-only, but indexed content still lands in persistent stores under the MEMEX data volume. The sampled evidence does not show backup scope, restore order, retention, delete-from-backup policy, or measured RPO/RTO.

**OWASP/security:** The sampled auth boundary is network locality, not demonstrated user/session authorization. The delete and verify routes are sensitive because they can remove or confirm presence of private material. Prompt/content injection, secret redaction quality, origin/host enforcement, retained metadata in forget logs, and model egress all remain unverified outside the sampled static paths.

**UI/UX/accessibility:** [TUI:19-40](https://github.com/knarayanareddy/MEMEX/blob/efe68e07df8d38988eb773f1485da64a0f375ba6/memex/tui/app.py#L19-L40) and the sampled web script show source/citation rendering and localhost API usage, but destructive-action confirmation, failure messaging, and keyboard/screen-reader behavior were not tested. A local interface still needs clear disclosure of what is collected, deleted, and retained.

## Production blockers and owner questions

Before any trust claim, the owner needs to decide: which directories and source types are in scope; whether the product supports only a single trusted desktop user or multiple local users; whether model/provider traffic may ever leave the host; what metadata may remain in forget logs; and what backup retention, delete-propagation, RPO and RTO are acceptable. Releasing beyond a tightly controlled local prototype without those decisions would overstate the sampled evidence.
